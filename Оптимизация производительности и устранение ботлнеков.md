## **1\. Инкрементальный парсинг Tree-sitter деградирует до O(N) и неверно считает старые координаты**

**Локация:** core/src/markdown/syntax.rs — методы IncrementalSyntaxTree::edit\_and\_parse и byte\_to\_point.

**Проблема:**

> * При каждом редактировании функция byte\_to\_point вызывается трижды и каждый раз итерируется с самого начала документа (text.char\_indices()) до нужного байта. В результате инкрементальный парсинг Tree-sitter, который должен работать за O(log N) от размера документа, превращается в три полных линейных прохода O(N) с декодированием UTF-8 на каждое нажатие клавиши.  
> * В byte\_to\_point поле Point::column в Tree-sitter ожидает смещение в байтах от начала строки, поэтому декодировать UTF-8 символы через char\_indices вообще не нужно.  
> * Кроме того, old\_end\_position вычисляется по уже изменённому тексту (new\_text), что даёт неверные координаты (row, column) при удалении или вставке переносов строк \\n и заставляет Tree-sitter инвалидировать больше узлов синтаксического дерева, чем нужно.

**Как оптимизировать:** Используйте уже существующий в Buffer (crop::Rope) B-дерево индекс строк, который находит строку и смещение за O(log N) без сканирования текста, либо передавайте Point до и после применения транзакции к Buffer:

`use crate::text::Buffer;`  
`use tree_sitter::{InputEdit, Point};`

`/// Вычисляет Point за O(log N) через B-дерево Rope вместо O(N) сканирования строки.`  
`pub fn byte_to_point_rope(buffer: &Buffer, byte_pos: usize) -> Point {`  
    `let clamped = byte_pos.min(buffer.byte_len());`  
    `let row = buffer.line_of_byte(clamped);`  
    `let line_start = buffer.byte_of_line(row);`  
    `Point {`  
        `row,`  
        `column: clamped - line_start,`  
    `}`  
`}`

Если в месте вызова доступен только срез или нужно обновить edit\_and\_parse, вычисляйте start\_position и old\_end\_position **до** модификации Buffer (через byte\_to\_point\_rope), а new\_end\_position — **после** модификации, передавая в parser.parse\_with замыкание по чанкам Rope::byte\_slice(byte..).chunks() вместо аллокации всей строки new\_text: \&str:

`pub fn edit_and_parse_rope(`  
    `&mut self,`  
    `input_edit: InputEdit,`  
    `rope: &crop::Rope,`  
`) -> SyntaxSnapshot {`  
    `if let Some(ref mut old_tree) = self.tree {`  
        `old_tree.edit(&input_edit);`  
    `}`  
    `let len = rope.byte_len();`  
    `let new_tree = self`  
        `.parser`  
        `.parse_with_options(`  
            `&mut |byte_offset, _point| {`  
                `if byte_offset >= len {`  
                    `&[]`  
                `} else {`  
                    `rope.byte_slice(byte_offset..)`  
                        `.chunks()`  
                        `.next()`  
                        `.map_or(&[], str::as_bytes)`  
                `}`  
            `},`  
            `self.tree.as_ref(),`  
            `None,`  
        `)`  
        `.expect("Incremental reparse failed");`

    `self.tree = Some(new_tree.clone());`  
    `SyntaxSnapshot::new(new_tree)`  
`}`

## **3\. Полное сканирование буфера на каждый шаг поиска (literal\_search)**

**Локация:** core/src/vim/motion/search.rs — функция literal\_search.

**Проблема:**

> * Замыкание find всегда сканирует **весь буфер от 0 до buffer.byte\_len()**, даже если при поиске вперёд (forward \== true) совпадение найдено сразу после position.  
> * При передаче префикса повторения (count \> 1, например 10n) цикл for \_ in 0..count { current \= find(current)?; } сканирует весь буфер с нуля count раз (сложность O(count \* N)).  
> * Побайтовый цикл Кнута — Морриса — Пратта (for \&byte in chunk.as\_bytes()) с внутренним while мешает автовекторизации (SIMD).

**Как оптимизировать:**

> 1. При поиске вперёд (forward \== true) начинайте обход со среза position..buffer.byte\_len() и прерывайте поиск сразу, как только найдено count-е совпадение. Только если до конца файла нашлось меньше count совпадений, продолжайте с начала файла (0..position).  
> 2. При поиске назад (forward \== false) достаточно одного прохода по всему буферу (или обратного прохода), сохраняющего кольцевой буфер последних count совпадений до position, вместо count полных проходов.

`pub fn literal_search(`

    `pos: usize,`  
    `query: &str,`  
    `forward: bool,`  
    `count: usize,`

        `return None;`  
    `}`

    `for i in 1..needle.len() {`  
        `while matched > 0 && needle[i] != needle[matched] {`  
            `matched = failure[matched - 1];`  
        `}`  
        `if needle[i] == needle[matched] {`  
            `matched += 1;`  
        `}`  
        `failure[i] = matched;`  
    `}`

    `let pos = pos.min(buffer.byte_len());`

    `if forward {`  
        ``// 1. Ищем вперёд от `pos`, останавливаясь сразу на count-м совпадении``

        `let mut matched = 0;`  
        `let mut offset = 0;`  
        `let mut first_in_wrap = None;`

        `for chunk in buffer.slice(0..buffer.byte_len()).chunks() {`  
            `for &byte in chunk.as_bytes() {`  
                `while matched > 0 && byte != needle[matched] {`  
                    `matched = failure[matched - 1];`  
                `}`  
                `if byte == needle[matched] {`  
                    `matched += 1;`  
                `}`

                `}`  
            `}`  
        `}`

        `first_in_wrap?;`  
        `let mut all_matches = Vec::new();`  
        `matched = 0;`  
        `offset = 0;`  
        `for chunk in buffer.slice(0..buffer.byte_len()).chunks() {`  
            `for &byte in chunk.as_bytes() {`  
                `while matched > 0 && byte != needle[matched] {`  
                    `matched = failure[matched - 1];`  
                `}`  
                `if byte == needle[matched] {`  
                    `matched += 1;`  
                `}`  
                `offset += 1;`  
                `if matched == needle.len() {`  
                    `all_matches.push(offset - needle.len());`  
                    `matched = failure[matched - 1];`  
                `}`  
            `}`  
        `}`  
        `let first_after = all_matches.partition_point(|&m| m <= pos);`  
        `let idx = (first_after + count - 1) % all_matches.len();`  
        `Some(snap_grapheme(buffer, all_matches[idx]))`  
    `} else {`  
        ``// Для обратного поиска собираем все позиции за ОДИН проход вместо `count` проходов``  
        `let mut all_matches = Vec::new();`  
        `let mut matched = 0;`  
        `let mut offset = 0;`  
        `for chunk in buffer.slice(0..buffer.byte_len()).chunks() {`  
            `for &byte in chunk.as_bytes() {`  
                `while matched > 0 && byte != needle[matched] {`  
                    `matched = failure[matched - 1];`  
                `}`  
                `if byte == needle[matched] {`

`}`

## **4\. Избыточные B-tree запросы и проверки графем в движениях курсора (eval\_motion и word.rs)**

**Локация:** core/src/vim/motion/cursor.rs и core/src/vim/motion/word.rs.

**Проблема:**

> * В eval\_motion для Motion::Left и Motion::Right внутри цикла for \_ in 0..count на **каждой итерации** вызываются buffer.line\_of\_byte(current) и buffer.byte\_of\_line(...), а в Motion::Right ещё и создаётся срез buffer.slice(current..next\_line\_start).chars().next(). Поскольку h и l никогда не переходят на другую строку, границы текущей строки постоянны на протяжении всего цикла.  
> * В core/src/vim/motion/word.rs функция word\_continuation вызывает snap\_grapheme(buffer, position) при несовпадении категории символа. При этом snap\_grapheme создаёт GraphemeCursor и делает два прохода (grapheme\_next \+ grapheme\_prev). Если символ ASCII (c.is\_ascii()), он гарантированно не является не-первым кодовым пунктом составной графемы (кроме \\n в \\r\\n, который уже отсечён проверкой \!c.is\_whitespace()), поэтому вызов snap\_grapheme для ASCII-символов полностью избыточен.

**Как оптимизировать:** Вынесите вычисление границ строки за пределы цикла 0..count в Motion::Left и Motion::Right, а в word\_continuation добавьте быстрый путь для ASCII:

`// В core/src/vim/motion/cursor.rs:`  
`Motion::Left => {`  
    `let line_start = buffer.byte_of_line(buffer.line_of_byte(current));`  
    `for _ in 0..count {`  
        `if current <= line_start {`  
            `break;`  
        `}`  
        `if let Some(prev) = buffer.grapheme_prev(BytePos::new(current))`  
            `&& prev.get() >= line_start`  
        `{`  
            `current = prev.get();`  
        `} else {`  
            `break;`  
        `}`  
    `}`  
`}`  
`Motion::Right => {`  
    `let line_idx = buffer.line_of_byte(current);`  
    `let content_end = line_content_end(buffer, line_idx);`  
    `for _ in 0..count {`  
        `if current >= content_end {`  
            `break;`  
        `}`  
        `if let Some(next) = buffer.grapheme_next(BytePos::new(current))`  
            `&& next.get() <= content_end`  
        `{`  
            `// В normal mode не встаём на конец строки (позицию LF/CRLF)`  
            `if next.get() < content_end {`  
                `current = next.get();`  
            `} else {`  
                `break;`  
            `}`  
        `} else {`  
            `break;`  
        `}`  
    `}`  
`}`

## **5\. Квадратичный поиск code\_ranges и find("\]\]") при парсинге Markdown**

**Локация:** core/src/markdown/facts.rs (MarkdownFacts::extract), core/src/markdown/style/tags.rs (color\_spans) и core/src/markdown/style/protection.rs (validate\_protection).

**Проблема:**

> * В MarkdownFacts::extract и color\_spans список диапазонов кода code\_ranges формируется из pulldown\_cmark уже отсортированным по возрастанию и без пересечений. Однако в Pass 2 и Pass 3 проверка вхождения в блок кода выполняется линейным поиском code\_ranges.iter().any(|r| r.contains(\&i)). На документах с большим количеством inline-кода это даёт O(N \* C) вместо O(log C).  
> * В Pass 2 (facts.rs) и в validate\_protection (protection.rs) при встрече \[\[ вызывается text\[i \+ 2..\].find("\]\]"), который сканирует текст **до самого конца файла**. Если в документе встретится незакрытая \[\[ (или несколько таких последовательностей), find("\]\]") будет повторно сканировать весь остаток документа на каждую \[\[, приводя к сложности O(N^2). Кроме того, wiki-ссылка в Markdown не может пересекать границу строки \\n.

**Как оптимизировать:**

> 1. Замените code\_ranges.iter().any(...) на бинарный поиск через partition\_point за O(log C).  
> 2. Ограничьте поиск закрывающих \]\] концом текущей строки (\\n), что исключает квадратичную сложность на незакрытых скобках и соответствует синтаксису wiki-ссылок:

``/// Проверка попадания позиции `pos` или пересечения диапазона `target` с отсортированными `code_ranges` за O(log C).``  
`fn overlaps_code_range(code_ranges: &[Range<usize>], target: Range<usize>) -> bool {`  
    `let idx = code_ranges.partition_point(|r| r.end <= target.start);`  
    `code_ranges`  
        `.get(idx)`  
        `.is_some_and(|r| r.start < target.end)`  
`}`

`// В Pass 2 (core/src/markdown/facts.rs):`  
`if overlaps_code_range(&code_ranges, i..i + 1) {`  
    `i += 2;`  
    `continue;`  
`}`  
`// Ограничиваем поиск "]]" текущей строкой:`  
`let search_slice = &text[i + 2..];`  
`let line_limit = search_slice.find('\n').unwrap_or(search_slice.len());`  
`if let Some(close_idx) = search_slice[..line_limit].find("]]") {`  
    `let end = i + 2 + close_idx + 2;`

    `let link = LinkOccurrence::parse_wiki_inner(inner, i..end, 0);`  
    `wiki_links.push(link);`  
    `i = end;`  
    `continue;`  
`}`

## **6\. Многократная перекомпиляция KeymapConfig и квадратичная валидация O(B^2)**

**Локация:** core/src/config/mod.rs и core/src/config/compiled.rs.

**Проблема:**

> * Методы KeymapConfig::has\_binding\_or\_prefix и KeymapConfig::available\_hints при **каждом вызове** выполняют self.compile().  
> * Внутри compile() вызывается self.validate(), который:  
  1. Заново аллоцирует CommandRegistry::default() (вектор из десятков CommandSpec, каждый со своим Vec\<CommandContext\>).  
  2. Выполняет вложенный цикл O(B^2) по всем привязкам клавиш (for (i, a) ... for (j, b)) и для каждой привязки делает линейный поиск registry.get(\&a.command).  
> * Затем compile() строит дерево BTreeMap\<Mode, BTreeMap\<Vec\<Key\>, Vec\<usize\>\>\>, аллоцируя Vec\<Key\> на каждый префикс каждой команды, клонирует весь self.bindings и создаёт **второй** экземпляр CommandRegistry::default().  
> * В CompiledKeymap::lookup и hints снова вызывается self.registry.require(...), который линейно ищет команду в Vec\<CommandSpec\>.

**Как оптимизировать:**

> 1. В CommandRegistry добавьте индекс или отсортируйте specs по CommandId, либо используйте HashMap\<CommandId, usize\> для поиска за O(1).  
> 2. В KeymapConfig::validate замените двойной цикл O(B^2) на сортировку ссылок по (mode, \&keys) за O(B log B): после лексикографической сортировки дубликаты и конфликтующие префиксы гарантированно находятся на соседних позициях (windows(2)).

`pub fn validate(&self) -> Result<(), KeymapError> {`  
    `if self.bindings.len() > 4096 {`  
        `return Err(KeymapError::InvalidBinding("more than 4096 bindings".into()));`  
    `}`  
    `let registry = CommandRegistry::default();`  
    `for a in &self.bindings {`  
        `if a.keys.len() > 32 {`  
            `return Err(KeymapError::InvalidBinding("key sequence exceeds 32 keys".into()));`  
        `}`  
        `if a.keys.is_empty() {`  
            `return Err(KeymapError::InvalidBinding("empty key sequence".into()));`  
        `}`  
        `registry.get(&a.command).map_err(KeymapError::Registry)?;`  
    `}`

    `// Сортируем ссылки за O(B log B) вместо O(B^2)`  
    `let mut sorted: Vec<&KeyBinding> = self.bindings.iter().collect();`  
    `sorted.sort_by(|a, b| a.mode.cmp(&b.mode).then_with(|| a.keys.cmp(&b.keys)));`

    `for pair in sorted.windows(2) {`  
        `let (a, b) = (pair[0], pair[1]);`  
        `if a.mode == b.mode {`  
            `if a.keys == b.keys {`  
                `return Err(KeymapError::DuplicateBinding {`  
                    `mode: a.mode,`  
                    `keys: a.keys.clone(),`  
                `});`  
            `}`  
            `if b.keys.starts_with(&a.keys) {`  
                `return Err(KeymapError::ShadowedPrefix {`  
                    `prefix: a.keys.clone(),`  
                    `conflicting_key: b.keys[a.keys.len()],`  
                `});`  
            `}`  
        `}`  
    `}`  
    `Ok(())`  
`}`

## **7\. Постоянные реаллокации в History::enforce\_memory\_limit и посимвольная запись в режиме вставки (Insert)**

**Локация:** core/src/text/history.rs и core/src/vim/execute/mod.rs (feed\_key), core/src/vim/execute/repeat.rs.

**Проблема:**

> * **В History::enforce\_memory\_limit (core/src/text/history.rs):** внутри цикла while self.total\_bytes() \> self.max\_bytes вызываются self.undo\_stack.shrink\_to\_fit() и self.redo\_stack.shrink\_to\_fit(). Как только история буфера достигает лимита памяти, каждая следующая транзакция вызывает shrink\_to\_fit(), заставляя аллокатор перевыделять и копировать кольцевой буфер VecDeque, а при следующей правке снова расширять его.  
> * **В VimState::feed\_key и run\_command (core/src/vim/execute/mod.rs, repeat.rs):** при вводе текста в режиме Mode::Insert каждый нажатый символ превращается в Command::TextCommit(c.to\_string()), который затем клонируется в repeat\_command, клонируется в macro\_buffer и пушится отдельным элементом в self.current\_edit. **Как оптимизировать:**

## **8\. Избыточные fsync (до 5 раз за вызов) и повторное чтение .snap-файлов в RecoveryManager::write\_snapshot**

**Локация:** store/src/recovery.rs — методы write\_snapshot и valid\_snapshots.

**Проблема:**

> * При каждом сохранении аварийного снапшота write\_snapshot выполняет до **5 вызовов sync\_all() (fsync)**:

  2. На корневой директории хранилища (root);  
  3. На временном файле снапшота (file.sync\_all());

> * Внутри write\_snapshot вызывается self.valid\_snapshots(key.buffer\_id)?, который открывает, **полностью вычитывает с диска в память и считает SHA-256** для каждого существующего снапшота этого буфера.

**Как оптимизировать:**

> 1. Синхронизируйте .truff и root только при фактическом создании директории (if \!self.recovery\_dir.exists()).

## **1\. Принудительный сброс кэша вёрстки до конца файла при быстром вводе (invalidate\_suffix \= true)**

**Локация:** core/src/workspace/changes.rs (Workspace::notify\_buffer\_change) и core/src/workspace/dispatch.rs (Effect::InvalidateView).

**Проблема (FPS & CPU):**

> * В notify\_buffer\_change при слиянии двух изменений одного буфера, произошедших до следующей отрисовки кадра (например, быстрый набор текста, вставка или выполнение макроса), безусловно выставляется флаг previous.invalidate\_suffix \= true.  
> * Для UI-рендерера invalidate\_suffix \= true означает необходимость выбросить закэшированную разметку строк (line wrapping, глифы, ширины символов) от места правки **до самого конца документа**.  
> * Кроме того, Action::MoveCursor, Action::Scroll, Action::FocusView и Action::ApplyEdit порождают один и тот же эффект Effect::InvalidateView(view\_id). Из-за этого UI не может отличить обычный сдвиг каретки (h/j/k/l) от изменения текста буфера без дополнительных проверок ревизии.

**Как оптимизировать:**

> 1. Храните в BufferChange точный сдвиг байтов delta: isize и аккумулируйте диапазоны при слиянии правок. Тогда UI сможет пересчитать шейпинг только для изменённого диапазона new\_range, а для всех строк ниже — просто прибавить delta к их стартовым байтовым смещениям за O(1) без повторного вызова текстового шейпера.  
> 2. Разделите Effect::InvalidateView на гранулярные флаги инвалидации, чтобы при движении курсора перерисовывался только слой каретки/выделения.

`// В core/src/workspace/changes.rs:`  
`#[derive(Debug, Clone, PartialEq, Eq)]`  
`pub struct BufferChange {`  
    `pub buffer_id: BufferId,`  
    `pub revision: u64,`  
    `/// Диапазон в координатах ДО первой необработанной правки кадра.`  
    `pub old_range: std::ops::Range<usize>,`  
    `/// Диапазон в координатах ПОСЛЕ последней правки кадра.`  
    `pub new_range: std::ops::Range<usize>,`  
    `/// Суммарное изменение длины буфера в байтах (new_len - old_len).`  
    `pub net_delta: isize,`  
    `pub invalidate_suffix: bool,`  
`}`

`impl Workspace {`  
    `pub(super) fn notify_buffer_change(&mut self, buffer_id: BufferId, changes: &ChangeSet) {`  
        `if changes.is_empty() {`  
            `return;`  
        `}`  
        `self.buffer_changes`  
            `.retain(|notice| self.buffers.get_buffer(notice.buffer_id).is_some());`  
        `let Some(buffer) = self.buffers.get_buffer(buffer_id) else {`  
            `return;`  
        `};`

        `let start = changes.changes().iter().map(|c| c.old_range.start).min().unwrap_or(0);`  
        `let old_end = changes.changes().iter().map(|c| c.old_range.end).max().unwrap_or(start);`  
        `let net_delta: isize = changes.changes().iter().map(|c| c.delta).sum();`  
        `let new_end = ((old_end as isize) + net_delta).max(start as isize) as usize;`  
        `let new_end = new_end.min(buffer.byte_len());`  
        `let grouped = changes.batches().count() > 1;`

        `if let Some(prev) = self.buffer_changes.iter_mut().find(|n| n.buffer_id == buffer_id) {`  
            `// Переводим старый new_range в новые координаты с учётом новой правки:`  
            `let merged_start = prev.old_range.start.min(start);`  
            `// Если новая правка произошла внутри или сразу после предыдущей:`  
            `let prev_old_end_in_initial = if old_end <= prev.new_range.end {`  
                `prev.old_range.end`  
            `} else {`  
                `((old_end as isize) - prev.net_delta).max(prev.old_range.end as isize) as usize`  
            `};`  
            `prev.revision = buffer.revision();`  
            `prev.old_range = merged_start..prev_old_end_in_initial;`  
            `prev.net_delta += net_delta;`  
            `let merged_new_end = ((prev.old_range.end as isize) + prev.net_delta)`  
                `.max(merged_start as isize) as usize;`  
            `prev.new_range = merged_start..merged_new_end.min(buffer.byte_len());`  
            `prev.invalidate_suffix |= grouped;`  
        `} else {`  
            `self.buffer_changes.push(BufferChange {`  
                `buffer_id,`  
                `revision: buffer.revision(),`  
                `old_range: start..old_end,`  
                `new_range: start.min(new_end)..new_end,`  
                `net_delta,`  
                `invalidate_suffix: grouped,`  
            `});`  
        `}`  
    `}`  
`}`

## **2\. Парсинг всего документа и аллокация полной строки для отрисовки цветов (color\_spans)**

**Локация:** core/src/markdown/style/tags.rs — функция pub fn color\_spans(text: \&str) \-\> Vec\<ColorSpan\>.

**Проблема (RAM & FPS):**

> * Сигнатура color\_spans(text: \&str) требует непрерывного среза \&str. Так как текст в редакторе хранится в crop::Rope, UI перед вызовом color\_spans вынужден вызывать buffer.as\_str(), копируя до 16 МиБ текста в новую String в куче.  
> * Внутри color\_spans запускается pulldown\_cmark::Parser::new(text) по **всему тексту документа**, чтобы собрать вектор code со всеми блоками кода, а затем сканируется весь текст на наличие \<span style="color:\#.  
> * При отрисовке на экране видны только 40–80 строк вьюпорта, поэтому парсить весь 16-мегабайтный файл ради подсветки \<span...\> на видимых строках крайне расточительно.

**Как оптимизировать:** Вычисляйте ColorSpan только для видимого диапазона байтов вьюпорта (viewport\_range: Range\<usize\>), используя SyntaxSnapshot (Tree-sitter) для проверки, не находится ли тег внутри блока кода, и читая строки напрямую из Buffer без buffer.as\_str():

`use crate::text::Buffer;`

`/// Извлекает цветовые спаны ТОЛЬКО для видимых строк экрана без аллокации всего буфера.`  
`pub fn color_spans_in_viewport(`

    `syntax: Option<&SyntaxSnapshot>,`  
    `viewport_lines: Range<usize>,`

    `let prefix = "<span style=\"color:#";`  
    `let end_line = viewport_lines.end.min(buffer.line_len());`

        `let line_start = buffer.byte_of_line(line_idx);`  
        `let line_end = if line_idx + 1 < buffer.line_len() {`  
            `buffer.byte_of_line(line_idx + 1)`  
        `} else {`  
            `buffer.byte_len()`  
        `};`

        `line_buf.clear();`  
        `for chunk in buffer.slice(line_start..line_end).chunks() {`  
            `line_buf.push_str(chunk);`  
        `}`

        `let mut offset = 0;`  
        `while let Some(relative) = line_buf[offset..].find(prefix) {`

            `let hex_start = local_start + prefix.len();`

            `};`

            `{`  
                `continue;`  
            `}`  
            `let local_content_start = hex_end + 2;`

            `};`  
            `let local_close_start = local_content_start + close_rel;`

            `let abs_start = line_start + local_start;`  
            `let abs_end = line_start + local_end;`

            `// Проверяем по Tree-sitter за O(log N) вместо полного прохода pulldown-cmark:`

                        `return true;`  
                    `}`  
                    `node_opt = node.parent();`  
                `}`

            `});`

                `continue;`

                `closing: (line_start + local_close_start)..abs_end,`  
                `rgba: [channel(0), channel(2), channel(4), 255],`  
            `});`  
        `}`  
    `}`  
    `spans`  
`}`

`/// Проверяет, есть ли в строке хотя бы один '\n', перед которым нет '\r'.`

        `if b == b'\n' && (i == 0 || bytes[i - 1] != b'\r') {`

        `}`  
    `}`  
    `false`  
`}`

### **9\. Сдвиг всей строки в памяти при text.insert\_str(0, nl) в VimState::paste и дублирование Registers**

**Локация:** src/vim/execute/editing.rs (VimState::paste, VimState::operator) и src/text/history.rs.

**Проблема:**

> * В VimState::paste (src/vim/execute/editing.rs) сначала создаётся let mut text \= String::new(); **без предварительного резервирования ёмкости (with\_capacity)**, затем в цикле 0..count туда копируется reg.text.  
> * После этого для построчной вставки (RegisterKind::Linewise) в конец файла без завершающего перевода строки вызывается:  
>   `text.insert_str(0, nl);`

>   Вызов insert\_str(0, nl) сдвигает **весь сгенерированный буфер text** в памяти на 1–2 байта вправо (memmove всего буфера), хотя условие insert \== buffer.byte\_len() && insert \> 0 && line\_content\_end(buffer, line) \== insert известно **до** заполнения text\!  
> * Кроме того, структура History (src/text/history.rs) внутри каждого Buffer хранит поле registers: Registers, которое в реальном приложении не используется (всё редактирование в Vim идёт через VimState::registers), но создаёт пустую HashMap в каждом открытом буфере.

**Как исправить:** Вычисляйте позицию вставки pos и необходимость префикса nl **до** сборки строки text и сразу выделяйте точную ёмкость через String::with\_capacity:

`// В src/vim/execute/editing.rs (метод VimState::paste):`  
`let head = view.head();`  
`let line = buffer.line_of_byte(head.get());`  
`let nl = buffer.line_ending().as_str();`

`let (pos, need_leading_nl, need_trailing_nl) = if reg.kind == RegisterKind::Linewise {`  
    `let insert = if after {`  
        `if line + 1 < buffer.line_len() {`  
            `buffer.byte_of_line(line + 1)`  
        `} else {`  
            `buffer.byte_len()`  
        `}`  
    `} else {`  
        `buffer.byte_of_line(line)`  
    `};`  
    `let leading = insert == buffer.byte_len() && insert > 0 && line_content_end(buffer, line) == insert;`  
    `let trailing = insert < buffer.byte_len() && !reg.text.ends_with('\n');`  
    `(insert, leading, trailing)`  
`} else {`  
    `let insert = if after {`  
        `buffer`  
            `.grapheme_next(head)`  
            `.map_or(head.get(), BytePos::get)`  
            `.min(line_content_end(buffer, line))`  
    `} else {`  
        `head.get()`  
    `};`  
    `(insert, false, false)`  
`};`

`let sep_bytes = if reg.kind == RegisterKind::Linewise && !reg.text.ends_with('\n') {`  
    `nl.len() * count.saturating_sub(1)`  
`} else {`  
    `0`  
`};`  
`let total_cap = bytes`  
    `+ sep_bytes`  
    `+ if need_leading_nl { nl.len() } else { 0 }`

`if total_cap > buffer.max_file_bytes().saturating_sub(buffer.byte_len()) {`  
    `return self.error("Paste exceeds buffer size limit");`  
`}`

    `text.push_str(nl);`  
    `nl.len()`  
`} else {`  
    `0`  
`};`

    `text.push_str(&reg.text);`  
    `if reg.kind == RegisterKind::Linewise && !reg.text.ends_with('\n') && index + 1 < count {`  
        `text.push_str(nl);`  
    `}`  
`}`  
`if need_trailing_nl {`  
    `text.push_str(nl);`  
`}`
