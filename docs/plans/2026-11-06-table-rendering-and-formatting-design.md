# Дизайн поддержки рендеринга и умного форматирования таблиц в Truff

**Дата:** 2026-11-06  
**Статус:** Утверждено  

---

## 1. Контекст и цели

В текущей версии Truff строки таблиц Markdown рендерятся как отдельные независимые текстовые блоки `Paragraph` с базовой подсветкой разделителей `|` и заголовка. Так как ячейки в неформатированном Markdown имеют произвольную длину, моноширинный текст не совпадает по колонкам, строка-разделитель `|---|---|---|` отображается сырым текстом с зачёркиванием, а сетка таблицы отсутствует.

Согласно спецификации `00_MARKDOWN_EDITOR_BEHAVIOR_CONTRACT.md` (раздел 4.3):
* **Source**: `pipe source`
* **Live Preview**: `аккуратная сетка с редактируемым source`
* **Reading**: `таблица`

### Главные цели
1. **Ядро (`crates/core`)**: модуль умного форматирования таблиц `table.rs` и интеграция в `smart_edit.rs` (выравнивание ячеек пробелами, переходы по `Tab` / `Shift+Tab`, создание строк по `Enter`, выход из таблицы по `Enter` на пустой строке).
2. **Интерфейс (`crates/ui`)**: чистое табличное отображение в Live Preview и Reading mode (скрытие сырого текста `|---|---|---|`, компактная линия-разделитель между `thead` и `tbody`, стилизация вертикальных границ ячеек).
3. **Команды**: регистрация `:format-table` / `:table-format` в командной строке и registry.
4. **Инварианты Vim и Undo**: атомарные транзакции (`Transaction` + `UndoGroup`), мгновенный откат по `u`, раскрытие исходника при фокусе каретки в Live Preview.

## 2. Архитектура решения

### 2.1. `crates/core` — Модуль форматирования и умного редактирования
* **Парсер таблицы**:
  * Сканирует смежные строки вокруг курсора, начинающиеся и заканчивающиеся на `|`.
  * Разбивает строки на ячейки с учётом экранирования (`\|`).
  * Считывает настройки выравнивания колонок из строки-разделителя (`:---`, `:---:`, `---:`).
* **Форматирование колонок**:
  * Вычисляет ширину каждой колонки как максимум видимых длин символов/графем ячеек: $W_k = \max(\text{len}, 3)$.
  * Заполняет пробелами каждую ячейку в соответствии с выравниванием.
  * Генерирует форматированную строку разделителя с сохранением двоеточий.
* **Умный ввод (`smart_edit.rs`)**:
  * `Enter` на строке с контентом: форматирует таблицу и добавляет новую пустую строку с нужным числом колонок.
  * `Enter` на пустой строке таблицы: удаляет строку и выходит из таблицы обычным переводом строки.
  * `Tab` / `Shift+Tab`: перемещает курсор между ячейками, автоматически добавляя новую строку в конце таблицы при необходимости.

### 2.2. `crates/ui` — Рендеринг таблицы в Live Preview и Reading Mode
* **Скрытие служебной строки-разделителя (`table_delimiter`)**:
  * В Reading mode и в Live Preview (когда курсор не на строке-разделителе) текст строки `|---|---|---|` скрывается через `DisplayChunk::hidden` в `DisplayMap`.
  * Высота параграфа строки-разделителя уменьшается до компактного зазора (6–8 dp).
  * `paint.rs` отрисовывает тонкую аккуратную горизонтальную линию `painter.hline` цвета `border_subtle`.
  * Если курсор установлен на строку-разделитель в Live Preview, исходный текст разделителя раскрывается для прямого редактирования.
* **Стилизация границ и заголовка**:
  * Пайпы `|` стилизуются ненавязчивым цветом рамки `border_subtle` вместо яркого цвета текста.
  * Заголовок выделяется полужирным начертанием и мягкой полупрозрачной подложкой `bg_panel`.

### 2.3. Регистрация команд
* Команда `markdown.format_table` в `registry.rs`.
* Синонимы в командной строке: `:format-table`, `:table-format`, `:table`.

## 3. План тестирования и верификации
1. Unit-тесты форматирования таблиц в `crates/core/tests/table_format.rs`:
   * Выравнивание таблиц разной ширины колонок.
   * Сохранение двоеточий выравнивания (`:---`, `:---:`, `---:`).
   * Корректная обработка экранированных пайпов `\|`.
2. Unit-тесты `smart_edit` для таблиц в `crates/core/tests/smart_edit_tables.rs`:
   * `Enter` внутри таблицы добавляет строку с нужным числом колонок.
   * `Enter` на пустой строке таблицы выходит из таблицы.
   * `Tab` перемещает курсор в следующую ячейку.
3. UI-тесты в `crates/ui/tests/display.rs` и `crates/ui/tests/native.rs`:
   * Скрытие текста строки-разделителя при отсутствии курсора на ней.
   * Раскрытие текста разделителя при наведении курсора.
   * Отсутствие регрессий в существующих тестах.
4. Полная проверка: `cargo check`, `cargo test --workspace`, `cargo clippy`.
