# Декомпозиция крупных модулей

Цель: выделить самостоятельные ответственности существующего Core → Store → UI,
сохранить поведение редактирования, сохранения и восстановления. Исходное дерево чистое;
`rtk cargo test --locked --offline --workspace`: 161 тест, 31 набор, ошибок нет.

## Границы работы

- Native UI: отдельная отрисовка вкладок, статуса, дерева, backlinks, содержимого
  и подсказок; каждый диалог владеет своим состоянием. NativeApp только координирует кадр.
- Shell: дерево файлов, панели, Flash, адаптация редакторского ввода и маршрутизация клавиш.
- Workspace: протокол Store, публикация изменений, команды и приём событий.
- Vim: типы команд, парсер, маршрутизация исполнения, повтор/макросы, движения,
  объекты текста и поиск. Каноническая транзакция сохраняется.
- Store: жизненный цикл worker, наблюдение файлов, исполнение jobs; планирование
  файловых операций, переписывание ссылок и долговечное применение/восстановление.
- Markdown style: защищённые диапазоны, теги и транзакции форматирования.
- Buffer: идентификаторы/позиции и кодирование концов строк отдельно от редактирования.
- Overlays и performance scenarios: независимые контроллеры и сценарии в своих модулях.
- Config и Commands: определения, готовые настройки и работа с ними разделены.
- Application: жизненный цикл хранилища, обработчики событий двух workers,
  редактирование, файловые команды, ссылки и оформление имеют отдельные модули.
- Catalog: протокол, сканирование/индексация и исполнение jobs отделены от lifecycle;
  SQLite и таблицей идентификаторов по-прежнему владеет один worker.
- History: регистры отделены от undo/redo. Index: backlinks отделены от обновления индекса.
- Остальные файлы больше 300 строк проверяются на смешение ответственностей;
  связные алгоритмы и наборы тестов не дробятся ради числа строк.

## Делегирование

Luna выполняет только заранее определённые перемещения существующего кода,
с точным списком разрешённых файлов, сохранением тел функций и публичных сигнатур.
Архитектура, изменения состояния, concurrency, интеграция и итоговый review принадлежат
основной модели. Нет новых зависимостей, unsafe, динамического dispatch или потоков.

## Проверка

После каждого блока — focused check/tests. После интеграции:

```sh
rtk cargo fmt --all -- --check
rtk cargo check --locked --offline --workspace --all-targets
rtk cargo test --locked --offline --workspace --all-features
rtk cargo clippy --locked --offline --workspace --all-targets --all-features -- -D warnings
```

Для hot paths изменения алгоритмов допускаются только с baseline и повторным
измерением в release. Переносы кода сами по себе не считаются ускорением.

## Результат

В `crates/*/src` исходно было 13 файлов больше 500 строк; после декомпозиции — 0.
Максимум уменьшился с 1249 до 479 строк. Строки учитывают комментарии и встроенные
тесты; отдельные integration tests и build artifacts в эту метрику не входят.
Порог используется для проверки архитектуры, а не как доказательство её качества.

| Исходный модуль | Строк до | Наибольший файл соответствующей области после |
| --- | ---: | ---: |
| UI native | 1249 | 278 |
| UI shell | 1143 | 394 |
| Core workspace | 827 | 374 |
| Vim execute | 915 | 348 |
| Vim motion | 870 | 386 |
| Vim parser | 570 | 479 |
| Text buffer | 543 | 408 |
| Store worker | 608 | 234 |
| Store operations | 590 | 174 |
| Markdown style | 553 | 249 |
| UI display | 508 | 145 |
| UI performance scenarios | 835 | 151 |
| UI overlays | 504 | 207 |

Оставлены связные модули: парсер Vim, транзакционный Buffer, RecoveryManager,
реестр открытых буферов, семантика движений курсора, редакторские транзакции,
резолвер ссылок, адаптер IME и навигационная модель. Маршрутизация Shell и Vim
содержит центральные dispatchers; исполнители отдельных действий находятся
в соседних модулях. Эти файлы не разбиты на произвольные части ради размера.

Структурные улучшения включают явное владение состоянием диалогов, paragraph cache
и файлового watcher. `LinkSelection` теперь принадлежит Core/Markdown, Store
сохраняет совместимый re-export. Новые внутренние модули приватны, если их API
не нужен потребителям. Зависимости и crate graph не изменены.

Изменение публичного Rust API: поля диалогов `NativeApp` сгруппированы в
`app.dialogs.vault`, `app.dialogs.file` и `app.dialogs.folder`. Например,
`app.show_create_vault_dialog` заменён на `app.dialogs.vault.open`. Репозиторные callers
и GUI tests обновлены. Значения по умолчанию и действия диалогов сохранены.

## Замер рендерера

Из горячего цикла удалён диагностический вывод в stderr. Подсказки читаются
заимствованием без копирования WhichKeyOverlay. Paragraph refresh использует
существующий `DisplayMap::update` для совместного изменения курсора и выделения,
что исключает второй пересчёт при их одновременном изменении. Добавлен regression
test для раскрытия/скрытия Markdown spans и Unicode source/visual mapping.

Воспроизводимый CPU benchmark:

```sh
rtk proxy cargo run --locked --offline --release -p truff-ui --example native_viewport_bench
```

Данные: 30 000 строк Markdown с Unicode, viewport 1100×700; один прогревочный
кадр и 200 кадров движения курсора за запуск, пять запусков. Замер исключает
начальную раскладку, startup процесса, системное окно и GPU; desktop RSS не измеряется.

| Метрика | До выделения paragraph/viewport | После |
| --- | ---: | ---: |
| Медиана 200 кадров, ms | 32.904 | 33.419 |
| Минимум–максимум, ms | 32.786–33.124 | 31.719–35.561 |
| Построений layout, каждый запуск | 227 | 227 |
| Параграфов в кеше, каждый запуск | 78 | 78 |

Ускорение по этому короткому замеру не установлено: медиана выросла на 1.6%,
диапазоны перекрываются. Количество построений и размер viewport cache сохранены;
данные не устанавливают отсутствие регрессий для всех сценариев.
