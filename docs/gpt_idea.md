Из Aquilum я бы перенял 8 идей. Они особенно полезны для твоего редактора с Vim-навигацией, интерфейсом в стиле Obsidian и минимальным потреблением ресурсов.

## Лучшие идеи Aquilum

1\. Единая дизайн-система через токены

Перенять в первую очередь

В Aquilum оформление централизовано: цвета фона, текста, границ, тени, размеры и типографика определены в одной системе. CSS-токены преобразуются при сборке в Rust-константы, включая светлую и тёмную темы. При смене основного цвета приложение вычисляет согласованные оттенки для остальных компонентов.

Для твоего проекта: использовать такую систему для всех панелей, файлового дерева, редактора, which-key и оглавления. Тогда интерфейс будет визуально цельным, а оформление можно будет менять без переписывания виджетов.

[tokens.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/native/src/ui/tokens.rs) · [theme.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/native/src/ui/theme.rs)

2\. Live Preview без отдельного режима просмотра

Markdown хранится как обычный текст, но синтаксис визуально преобразуется. Например, `# Заголовок` показывается как заголовок, а маркер `#` скрывается, пока курсор не находится в соответствующей конструкции.

Aquilum хранит layout отдельно для абзацев, повторно использует неизменённые layout-объекты и рисует только видимую часть документа с запасом вокруг неё.

Для твоего проекта: перенять разделение между исходным Markdown, его синтаксической интерпретацией и визуальным представлением. Особенно полезно для Vim: motions должны работать по исходному тексту, независимо от скрытых Markdown-маркеров.

[ui/editor](https://github.com/Freaction/Aquilum/tree/main/aquilum-app/native/src/ui/editor)

3\. Виртуализированное дерево хранилища

Aquilum хранит состояние раскрытых папок и кэш файловой структуры. Вместо создания виджета для каждого файла он создаёт ограниченное окно строк: в реализации используется диапазон до 160 строк, а при прокрутке добавляется запас в 40 строк до видимой области.

Есть выделение нескольких файлов, перетаскивание, переименование и восстановление прокрутки.

Для твоего проекта: использовать эту идею как основу универсального древовидного навигатора. Один механизм отображения должен подходить для файлов, заголовков Markdown, буферов и впоследствии графа знаний в режиме дерева.

[file_tree/mod.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/native/src/ui/file_tree/mod.rs)

4\. Retained UI и типизированные ссылки на виджеты

Aquilum использует Masonry. Виджеты существуют независимо от кадров и сохраняют своё состояние. Для доступа к ним автор реализовал `Handle<W>`, который объединяет идентификатор виджета с его Rust-типом.

Виджеты запрашивают только необходимое обновление: изменение оформления может вызвать `request_paint_only()` вместо нового layout.

Для твоего проекта: такая система подходит для единой Vim-навигации по панелям. Активная панель получает команды через общий диспетчер, а конкретный виджет самостоятельно определяет допустимые действия.

[handle.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/native/src/ui/handle.rs) · [widgets.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/native/src/ui/widgets.rs)

5\. Отдельная система разрешения Markdown-ссылок

В Aquilum обнаружение ссылки в тексте отделено от открытия файла. Есть `Resolver`, который предоставляет подсказки, разрешает имена заметок и принимает запросы вроде открытия ссылки.

Поиск, индекс ссылок и их визуальное представление разделены.

Для твоего проекта: сделать ссылку полноценным объектом Vim-редактора. Тогда создание `[[заметка]]`, переход по ссылке, переименование связанного файла и навигация между backlinks будут использовать одну систему разрешения ссылок.

[resolve.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/native/src/ui/editor/resolve.rs) · [search/wiki](https://github.com/Freaction/Aquilum/tree/main/aquilum-app/core/src/search/wiki)

6\. Сохранение рабочего пространства

Aquilum сохраняет открытые вкладки, активный документ, состояние панелей, историю переходов и положение просмотра. Вкладки имеют собственные идентификаторы и могут менять порядок.

Для твоего проекта: перенять восстановление состояния, но расширить модель до Vim-буферов. Один буфер должен допускать несколько представлений, а закрытие вкладки не должно автоматически уничтожать несвязанный с ней текстовый буфер.

[tabs.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/native/src/tabs.rs) · [session.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/native/src/session.rs)

7\. Определение изменившейся области рендеринга

Aquilum сравнивает хеши графических команд двух кадров и определяет прямоугольник, который необходимо перерисовать. Затем `vello_cpu` растеризует соответствующую область.

Для твоего проекта: это полезно для курсора, выделения текста, изменения активной вкладки и подсказок which-key. Нет необходимости заново растеризовать весь интерфейс при каждом небольшом изменении.

Однако алгоритм Aquilum объединяет изменения в один прямоугольник. Для разнесённых изменений можно позднее использовать несколько областей.

[damage.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/native/src/render/damage.rs)

8\. Независимое ядро и событийная модель

`aquilum-core` не зависит от UI. Оно управляет файлами, поиском, индексами, историей и наблюдением за каталогами. Через `CoreEvent` изменения поступают в интерфейс.

Для твоего проекта: разделить хранилище документов, Vim-движок, индекс ссылок и UI. Тогда смена рендерера или файлового навигатора не должна затрагивать реализацию Markdown и команд редактирования.

[app_core.rs](https://github.com/Freaction/Aquilum/blob/main/aquilum-app/core/src/app_core.rs)

## Две идеи на будущее

Граф знаний с кэшированием. В Aquilum есть отдельные модули расчёта графа, его layout и отображения. Графические данные кэшируются с учётом версии индекса. Это хорошая основа для твоей идеи переключения между свободным графом, деревом и иерархическим представлением, без повторного построения всех связей при каждом переключении.

История заметок с восстановлением. Aquilum хранит историю изменений и позволяет восстанавливать версии. Для редактора с Vim-операторами стоит дополнить эту идею единым журналом действий, в котором можно отменять не только текстовые правки, но и перенос файлов, переименование и структурные изменения.

## Что я бы не копировал буквально

Самые хорошие идеи Aquilum не обязательно означают, что следует копировать их реализацию.

Его `String` как основной текстовый буфер недостаточно хорошо масштабируется на длинные документы с частыми вставками в начало. Для Vim-редактора стоит рассмотреть Rope или Piece Table.

Также в Aquilum пока нет нужного тебе единого Vim-движка и системы which-key. Их следует проектировать самостоятельно поверх общего реестра команд.

Мой выбор для первого этапа: дизайн-токены, файловое дерево, Live Preview, типизированные виджеты и модель рабочего пространства. Эти пять идей непосредственно определяют внешний вид и поведение редактора. Частичный рендеринг и сложную индексацию можно развивать после появления рабочего прототипа.

Код Aquilum распространяется по AGPL-3.0-only: архитектурные идеи можно использовать самостоятельно, но буквальное заимствование исходников требует соблюдения условий лицензии.
