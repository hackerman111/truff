# Инвентаризация рекомендаций по оптимизации

Источник: `Оптимизация производительности и устранение ботлнеков.md` (2352 строки). Строка в первом столбце указывает начало исходного раздела; идентификатор включает повторяющийся номер раздела и проход аудита. `внесено` означает, что изменение есть в рабочем diff, без утверждения о прохождении итоговых проверок; `проверено` означает только проверку указанного факта по исходникам; `частично` отмечает ограниченное решение; `неприменимо` означает отсутствие producer/callers в текущем production пути; `отклонено` сопровождается причиной. Актуальные результаты проверок и замеров записаны в `docs/perf/{core,store,ui}/README.md`; эта таблица не заявляет дополнительных результатов.

Порядок исполнения: **core → store → UI**. Внутри каждого этапа сначала закрепить инварианты и проверки, затем объединять пересекающиеся работы по каноническому владельцу. Лёгкие локальные задачи с чётким контрактом делегируются Luna; root держит алгоритмы, состояния и интеграцию. Таблица также фиксирует выполненные контракты, не объявляя проверки или замеры завершёнными.

## Основные конфликты и оговорки

- Источник смешивает наблюдения, гипотезы и готовые фрагменты кода. Ни один заявленный множитель, FPS/RAM эффект или сложность не считается измеренным в этой инвентаризации.
- Поиск L97: реализация-предложение собирает все совпадения в неограниченный Vec и меняет детали count/wrap; отдельная оптимизация не должна терять поиск на границах combining marks и overlapping совпадения.
- Keymap L319: сокращать повторную компиляцию можно только с инвалидацией по изменению конфигурации. Кэш на публичном изменяемом config без контроля изменений станет устаревшим.
- Перевод строки L2224: выбор первого `\n` отклонён, поскольку меняет mixed-newline файлы; сохраняем политику «если где-либо есть CRLF». Guard нормализации bare LF делегирован Luna.
- UI-кэш L516/L1038 зависит от корректных ChangeSet координат и отображения строк. Сначала core-инварианты, затем кэш UI.
- Store изменения индексов/FTS требуют совместимости существующей SQLite схемы; изменения rowid, stem и migration нельзя копировать как локальную замену SQL без проверки старых БД.
